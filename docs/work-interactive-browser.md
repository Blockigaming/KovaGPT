# Isolated Work browser

The interactive browser is disabled by default. It runs in a separate, digest-pinned Chromium image under the reviewed `runsc` runtime. Enabling the source requires an owner-configured runner, backend session policy, and successful signed readiness. This source change does not provision or activate a service.

The runner configuration is `KOVA_WORK_BROWSER_ENABLED=true`, `KOVA_WORK_BROWSER_IMAGE=<immutable sha256 image>`, and `KOVA_WORK_BROWSER_ORIGINS_JSON` containing one to twenty reviewed HTTPS origins. The browser image is built from `work-runner/browser-image`; its Playwright base and npm dependency lock are pinned. The normal runner HMAC identity, TLS endpoint, backend origin, durable owner retirement locks, and current account authorization remain required. A missing or invalid browser configuration does not silently choose a host browser.

Each browser session has an absolute five-minute lifetime, one networkless container, a read-only root filesystem, no host mounts, no inherited runner secrets, no container logs, one CPU, 768 MiB memory and 128 processes. Chromium receives no network interface. Every intercepted navigation, redirect, script, image and fetch request crosses the stdio broker. The broker rechecks current backend authority, validates the reviewed origin, resolves only public IPv4 destinations, rejects mixed public/private answers, pins the chosen address to a certificate-verified TLS connection, and rechecks authority before releasing response bytes. Browser WebSockets, service workers, downloads, popups and permission prompts are blocked.

Limits are eight concurrent network requests, 500 requests and 20 MiB of response bytes per session, 64 KiB per request body, 2 MiB per encoded or decoded response, and 10 seconds per network request. Container protocol and command queues have separate byte and count bounds. Authentication cookies live only in the temporary Chromium context. No cookies, storage-state bundle, screenshots, video, HAR, password values or console output are exported or stored in a Work run.

An owner opens or takes control only while the saved Work run is paused and has no outstanding step or effect. The owner view renders bounded text and opaque interactive targets; it does not insert remote HTML or JavaScript into KovaGPT. Owner commands can navigate, fill, click, press supported keys and scroll. Passwords travel transiently to this isolated session. Releasing control clears form values and gives the model access to the remaining authenticated browser session until its expiry. Users should release control only when they intend the model to read the signed-in site.

The model can request `browser_interact` with `snapshot`, `navigate`, `click`, or `scroll`. Each operation requires its own existing Work approval, exact canonical input, current saved step, one-use backend admission and monotonically increasing browser sequence. Model requests use GET or HEAD; entering credentials or sending other HTTP methods requires owner takeover. A click references an opaque target in an exact snapshot and rechecks that target's identity before acting. Page content remains untrusted task data.

Every command rechecks account retirement and backend authority. A command with an ambiguous result closes the session and must not be automatically replayed. Process loss also discards browser state; create a new session and sign in again when needed. Owner cleanup retires future writes, waits on the shared kernel ownership lock, removes all owner-labeled containers across instances, and confirms removal before returning a clean result. Expired-container cleanup also runs during readiness probes. A delayed blank container startup checks its absolute deadline before launching Chromium.

`tests/unit/work-browser*.test.mjs` exercises network, transport, ownership and fixed container orchestration. `tests/browser-runtime/work-browser-driver.test.mjs` uses real local Chromium with intercepted fixture traffic. The existing Work Sandbox Isolation workflow builds the exact browser image and runs `node work-runner/browser-image/acceptance.mjs --execute` under actual `runsc`, including namespace configuration, private-destination interception, owner credentials and replay denial. Hosted isolation results are required when Docker is unavailable in the source workspace.
