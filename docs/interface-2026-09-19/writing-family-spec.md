# Writing family — partial source specification

Reviewed 2026-09-19. **22 references = one hub + 21 tool pages.** These remain individually tracked. This packet establishes source-text coverage, not visual or interaction acceptance.

## Shared implementation contract (proposed for Kova)

Use one tool layout with a typed per-page configuration: stable page ID, route, title, purpose, input type, observed settings, separately verified option lists, follow-up actions, execution capability and output renderer. Reuse the existing app shell, composer primitives, menus, dialogs and accessibility conventions. Keep the hub as its own directory layout. Do not add Codex or out-of-scope provider links from the source shell.

Separate source observations from product decisions. A visible label is not a complete menu specification. An empty observed-label list means “not established by extraction”, not “the page has no controls”. Follow-up labels need real mapped destinations or actions; they must not become dead decorative buttons.

Kova state contract: empty input → valid input → submitting/streaming → result, with cancellation, retry, recoverable failure and preserved input. Disable duplicate submission; keep draft content after errors. Make output copy and reset work, announce status accessibly, restore focus after menus/dialogs, and handle mobile keyboards without obscuring the composer. Authentication and allowance errors must link to real account/plan flows. These are proposed requirements, not verified existing behavior.

Text generation tools need a real server-side model adapter. Citation tools need metadata validation and supported style rules. Word counting should run locally and deterministically. AI detection and plagiarism claims stay gated on an appropriate verified capability; do not substitute a plausible model answer for detection evidence. No new provider is authorized by this packet.
