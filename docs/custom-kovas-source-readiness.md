# Custom conversational Kovas

Custom Kovas are separate from saved Work agents. `/kovas` provides a private builder, saved-version inspection and restore, temporary streaming preview, and ordinary chat creation. `/assistants` reads the current public directory. The builder supports names, text/emoji icons, descriptions, instructions, starters, model modes, explicit tool/app choices, and frozen knowledge excerpts.

Private is the default. Publishing requires consent to the exact saved version. Owner edits create private versions and do not change the publication. Unlisted links contain a random capability in the URL fragment; the server stores its hash and grants only the verified viewer access to that publication epoch. Republish, unpublish, moderation and deletion revoke previous grants. Chat history stores only the Kova/version IDs, never a capability.

Knowledge is copied from the creator's own current Library or supplied text at save time. These snapshots are explicitly shared through model responses when published. Other callers never inherit the creator's live Library permissions, app connections, credentials or plan. Forking requires the publisher's permission and the caller's exact-version consent, producing a private independent copy. Deleting the original does not delete a previously authorized independent copy.

Every chat uses the current caller's verified account, plan, Lockdown settings and app scopes. Custom model modes cannot select arbitrary deployments. Historical attachments are rejected when files are disabled. Provider, image, web search and app execution recheck the current publication before outbound work. The selected Google tools are intersected with the caller's actual available tools; writes retain the existing confirmation flow. Deep Research starts from regular chat. Preview is Temporary Chat and does not save history or memory.

Limits are enforced in source and SQL: 100 Kovas per owner, 20 versions per Kova, ten knowledge excerpts, 30,000 characters per excerpt, 180,000 total knowledge characters and 256 KiB per saved configuration plus snapshots. Version storage is charged to the existing account quota and released on version/Kova deletion. Immutable mutation requests expire after seven days, before their eight-day receipt retention, preventing old creates from recreating deleted records after receipt cleanup. Metadata and bodies participate in the cumulative bounded account export; Auth deletion cascades all owned records.

Signed-in viewers can report current publications. `/admin/kovas` requires the existing operator-configured administrator allowlist; it exposes current published snapshots, never unpublished owner drafts. Moderators can block, restore and mark individual reports reviewed, with revision checks and bounded audit retention. The queue processes the oldest twenty open reports and advances after decisions. Reports preserve the reported version name even when its old version is deleted. Community listings make no claim that every entry received prior human review.

Executable checks are in `custom-kovas-lifecycle.test.mjs`, `custom-kovas-runtime.test.mjs` and `custom-kovas-principal.spec.ts`. They cover actual database roles without service-role Auth table SELECT, owner isolation, exact publication/fork consent, link revocation, immutable request expiry, quota settlement, moderation, historical file restrictions, current caller tool filtering, actual HTTP handler admission, and browser account-switch/reset races. Production activation still follows the repository's authorized migration and deployment process; this package performs no live migration, provider configuration or service write.
