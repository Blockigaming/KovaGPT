## Independent gaps first

1. **Support attachments are missing.** `/help` has no file input, attachment state, upload/remove/retry flow or attachment payload. `SupportForm` posts JSON text fields to `/api/public/help-submit`. `/contact-support` also yielded no attachment control. This is an independent missing UI/contract if the owner requires contact attachments; sending/sent/error states do not cover it.
2. **No public shared-chat link viewer was found.** Existing sharing sends an account-addressed read-only snapshot to another KovaGPT user and opens it inside Library. There is no dedicated public shared-chat viewer route, and no separate private/deleted/unavailable viewer screens. Library loading/error/empty/snapshot/revoke states partially cover authenticated sharing only. Do not count `/share-inbox` as a shared-chat viewer: it is a PWA incoming-text review flow.
3. **Cookie policy is explicitly provisional.** `/cookie-policy` exists, but its text says deployment-specific vendors and retention require review before publication. Acceptable-use and accessibility pages are short policy/guidance pages, not comprehensive audited policies or certification. This is a content/sign-off gap, not missing routing.
4. **Help answers are accordion articles, not separate help-article pages.** `/help` supplies searchable FAQ answers with stable FAQ anchors. If the owner expects independently navigable article-detail screens, those are not implemented by this Help flow. Existing publication/article routes are unrelated editorial content and must not be substituted.
5. **Status is guidance, not an incident dashboard.** `/status` explicitly disclaims automated incident monitoring and links to application health. Live component health, incident history and subscriptions are not present; do not invent operational success.
