# Core checklist coverage: Settings, authentication and billing (rows 24–45)

Source-only reconciliation, 2026-10-17. Row numbering follows the supplied ordered grouping: nine Settings rows, six authentication rows, seven pricing/billing rows. This is a coverage map, not a claim of full acceptance. No browser, tests, provider calls or build were performed for this mapping.

## Concrete remaining limitations first

- **Sessions (31):** Safety & security exposes bulk “Sign out other sessions.” There is no per-device session inventory or individual-session revoke UI. The inspected account routes expose current-session and revoke-others endpoints, not a session-list contract. Completing individual-device management would expand the existing account scope, rather than merely connect an existing form.
- **Profile (25):** Preferred name and contextual profile text are editable personalization. Account email is read-only, with explicit support guidance; no account email-change form exists. An account-profile editor beyond those controls is not demonstrated by this source.
- **Invoices/cancel/reactivate (44–45):** These are delegated to the configured Stripe billing portal. There is no local invoice list or native cancellation/reactivation workflow. The app exposes a portal link, cancellation status and support fallback, not a successful local substitute.
- **Current acceptance:** Historical backup coverage only traversed selected UI states. Current rendered/mobile/keyboard and real provider/device acceptance remain unverified. The owner prohibits browser use for this continuation. Existing source and synthetic fixtures must not be described as a completed real-account journey.
- **Previously concrete UI defects now fixed:** canceled trials acknowledge scheduled cancellation before trial-renewal text; Refund uses the existing explicit `LegalArticle` typography wrapper without changing policy text. Billing stale-completion/duplicate-click guards and recovery/onboarding focus/state fixes are present. This map does not re-test them.

Launcher integration and any eventual rendered execution are separate from defining these fixtures.
