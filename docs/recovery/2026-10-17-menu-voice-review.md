# Chat menus and staged voice controls

Owner requested a Rename icon and wider chat action menus without taller rows. Sidebar Rename now uses the same Lucide pencil treatment as its peer controls. Sidebar menu width is 240px, header menu 312px, with horizontal inset adjustments and viewport-safe clamping. Row heights are unchanged.

The empty composer opens a Voice dialog; text or attachments still switch the trailing action to Send. Voice is a staged workflow: explicitly start recording, review/edit the transcript, add it to the current draft, then use the existing chat Send control. Adding transcription appends to the latest draft instead of replacing newer text. Existing Kova authentication/model/entitlement/send contracts remain in effect. Completed assistant replies can be explicitly requested as speech, with native playback controls. This is not a continuous conversational voice session.

The voice dialog checks authenticated server capabilities, requests the microphone only after an explicit Start recording action, and handles unsupported/denied microphone access, cancellation, timeouts and stale account/chat results. Media tracks, requests and audio object URLs are released on close/context/account change and unmount. Recording stops at 59 seconds to leave codec headroom below the server’s strict 60-second ceiling. Audio is bounded locally and normalized to canonical PCM WAV; server validation derives duration from actual PCM bytes rather than supplied duration metadata.

The private review adapter advertises voice as disconnected and rejects audio requests. Its rendered preview cannot exercise live recording/transcription/playback. Mocked component/server/helper tests cover those paths without microphone access or provider spending. See docs/voice/elevenlabs-integration.md for server configuration and remaining operational checks. No key is embedded in the client or review package. Credential setup, actual provider verification, publication and deployment remain separate.
