# Executable staging validation

All tools emit redacted JSON and are read-only or dry-run by default.

| Command                                                                              | Purpose                                                                                | Mutation risk                                                                         | Credential requirement                                            |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `node scripts/staging-validation/environment-diff.mjs --input <names-or-json>`       | Compare deployed variable names to the environment contract                            | None                                                                                  | Sanitized names only                                              |
| `node scripts/staging-validation/azure-preflight.mjs --metadata <app.json>`          | Validate Container App metadata and immutable artifact                                 | None                                                                                  | None for fixture; Azure Reader for `--live`                       |
| `node scripts/staging-validation/azure-rollback.mjs ...`                             | Validate rollback targets and emit traffic command                                     | Dry-run only; emitted command changes staging traffic                                 | Sanitized revisions; Azure Contributor to execute emitted command |
| `node scripts/staging-validation/auth-migration-rehearsal.mjs --metadata <json>`     | Guard generation flags, synthetic source, connectivity, and empty destination          | None by default; never sends migration request                                        | Sanitized immediate preflight                                     |
| `node scripts/staging-validation/domain-callbacks.mjs --input <json>`                | Reject unsafe origins/callbacks                                                        | None                                                                                  | None                                                              |
| `node scripts/staging-validation/artifact.mjs`                                       | Validate container entrypoint, non-root runtime, lockfile, health and `.env` exclusion | None                                                                                  | None                                                              |
| `node scripts/staging-validation/external-harness.mjs <kind> --fixture <json>`       | Validate Supabase/Stripe/provider/OAuth/rate-limit/lifecycle execution prerequisites   | None; `--execute` still refuses to claim a live execution without an endpoint adapter | Sanitized fixture; live credentials remain external               |
| `npm run staging:validate -- --environment <file> --azure <file> --callbacks <file>` | Coordinate deterministic checks and explicitly list unexecuted live phases             | None                                                                                  | Sanitized metadata                                                |

The external harness deliberately does not accept secrets on its command line and does not fabricate network success. Live adapters must use secret references/environment injection in an authorized staging session.

The credential-backed adapters are `supabase-two-user.mjs` (owner read plus cross-user read/update/delete denial against pre-created disposable fixtures) and `provider-smoke.mjs` (one synthetic idempotent request capped at 64 output tokens). Both fail closed without `--execute`, HTTPS staging configuration, and environment-injected user credentials; neither prints tokens or response content.

`model-catalog.mjs` verifies every configured text role resolves to a registered catalog model with a billing dimension and explicitly separates catalog registration from provider availability. GPT-5.6 Sol is eligible only through the premium role/provider configuration; its live availability must be proven by the bounded provider smoke and is not assumed for Azure deployments.
