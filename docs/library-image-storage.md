# Private Library image storage

Image saves reserve the actual validated image byte length against the account's existing storage limit before any Storage upload. The immutable reservation binds the verified owner, logical Library item, generation, object path, MIME type, content digest and save fingerprint. The server uploads without overwrite, reads back a bounded object from the exact configured Storage origin, verifies its byte length and SHA-256, and then publishes Library metadata transactionally. Identical retries reuse the reservation; different content cannot overwrite a winning save. Image prompt text is charged separately by the normal Library current-text accounting.

Authenticated clients can read their own private images but cannot insert or delete Storage objects directly. Managed image metadata cannot rewrite its byte identity. Image deletion requires the displayed Library content generation, retires the exact immutable object, and releases its byte charge only after the Storage API reports success and the object metadata is absent. Legacy duplicate Library references retain their shared object until the final reference is removed. Direct Library metadata deletion still leaves a durable cleanup obligation.

The metadata-only migration accounts existing owner-prefixed Storage objects, including unregistered uploads, using actual Storage sizes. Unknown legacy sizes use the conservative 8 MiB bucket envelope. Existing image bytes are neither downloaded nor moved by the migration. Over-limit legacy accounts retain their files and can remove them; new reservations remain blocked until enough storage is freed.

Cleanup is bounded to 25 image obligations per invocation and remains retryable after a late upload or lost response. The existing secret-authenticated Storage cleanup worker drains both generation ledgers. Account deletion waits for live upload leases, completes Project/evidence/original-file cleanup, and then retires and drains image bytes before Auth deletion. Minimal immutable paths and generation tombstones survive Auth deletion to permit repeated cleanup; private fingerprints and digest metadata are cleared after successful removal. These operational cleanup rows are excluded from account exports; the user's original image bytes, Library metadata and prompt remain covered by the existing owner-scoped export.

Limits: images are at most 8 MiB each; the existing Free/Plus/Pro account byte limit applies, with a 50,000 lifetime image-generation safety ceiling per account. This package supplies repository source and tests only. Applying the migration and scheduling the existing authenticated cleanup worker remain deployment actions.
