# Kova route inventory

Source snapshot **`1eb7ef53`**, audited **2026-09-05**. These are implemented entry points, not a statement that they are deployed. Route counts are deliberately omitted: endpoints and dynamic routes are not feature-completion units. Source lives under `src/routes`; generated route trees are build products.

| Entry point                                                                          | User/data boundary                          | Capability evidence and release status                                                                     |
| ------------------------------------------------------------------------------------ | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `/`                                                                                  | Mixed guest/current account                 | Chat, Temporary, history and Work controls; source/tests exist, final deployment unverified.               |
| `/projects`, `/projects/$projectId`, `/projects/$projectId/chat/$chatId`             | Current Project membership/role             | Files/context/templates/comments and collaboration; no inherited foreign-account rights.                   |
| `/library`, `/files`, `/images`                                                      | Guest-local or current owner                | Originals/folders/versions/private image lifecycle; provider/storage readiness applies.                    |
| `/work`, `/scheduled-tasks`                                                          | Current owner; signed execution readiness   | Planning/control/history are distinct from actual admitted runner/Task execution.                          |
| `/sites`                                                                             | Owner/current viewer; separate asset origin | Static lifecycle, access and immutable versions; co-editing package pending. No arbitrary backend hosting. |
| `/organization`, `/trusted-contacts`, `/study`                                       | Exact principal/role/consent                | Organization controls, targeted contacts and practice progress; policy/operational gates remain explicit.  |
| `/memory`, `/apps`, `/context-packs`, `/prompt-studio`                               | Current owner/connection grant              | Scoped context and connector functionality; reusable skills are separate source work.                      |
| `/research-planner`, `/research-assistant`, `/ai-writer`, `/summary`, `/code-helper` | Current model/provider policy               | Bounded focused workflows, not independent model or provider guarantees.                                   |
| `/developers`, `/developers/console`, `/developers/pricing`, `/developers/$docSlug`  | Public docs/current developer owner         | Kova models/quotes/usage/funding/keys/private files; paid activation requires approved contracts.          |
| `/pricing`, `/help`, `/getting-started`, `/contact-support`, `/status`               | Public/mixed                                | Truthful configured capabilities; no enterprise/compliance promises from static content.                   |
| `/privacy`, `/terms`, `/refund`, `/ai-safety`                                        | Public policy drafts                        | Owner/legal review is required; code audit is not approval.                                                |
| `/api/*`, `/mcp`, callbacks, internal workers, sitemap endpoints                     | Explicit user/service/protocol boundaries   | Not product pages or ordinary navigation. No private content is public by virtue of a route.               |
| Pending `/kovas`, `/discovery` and OAuth/SCIM additions                              | Per-package principal/role gates            | Do not count until the source package and generated routing are integrated.                                |

Responsive, accessibility, loading/empty/error/offline, device, role and recovery validation are separate acceptance dimensions for each applicable route. See [the capability ledger](../feature-parity.md) and [current work queue](../remaining-chatgpt-gaps.md). No empty aliases are added to imitate a reference URL.
