# Workspace search

Kova Brain now has authenticated search across current saved workspace sources: Projects, Project chat titles, ready Project file names, Project memory, Library titles/saved text, Context Pack descriptions, research queries/reports, scheduled-task prompts, prompt templates, and goals. It does not read local-only conversations, binary file contents, signed URLs, connector credentials, or shared-chat snapshots.

Keyword search works without an embedding provider. When the separately enabled semantic service has usable indexed vectors, results are ranked using exact cosine similarity plus keyword rank. The interface identifies the mode actually used. Provider failures, exhausted semantic budgets, and missing compatible vectors fall back to keyword search; database/auth failures remain explicit errors. Search considers at most 2,000 recent currently accessible records and returns at most 30. Saved text is bounded to the first 4,000 Unicode characters and titles to 200; this is deliberately not an unlimited full-document index.

The source view uses `security_invoker` and the underlying existing RLS policies. The search RPC also uses invoker privileges and the caller's authenticated client. Both the derivative-index policy and the final join check the source's current presence, permissions, and digest. Revoking Project membership therefore removes access without waiting for reindexing. Results always contain current source titles/snippets, not stale copies. Search requests and responses use private/no-store handling, and the browser pins the submitting account token and discards replaced or hidden results.

Only the service role can claim/settle jobs or mutate the derivative index. Jobs retain source identifiers, digests, lease/revision state, and vectors; raw source text is read at claim time and is not durably copied to the queue. Source changes invalidate old embeddings and leases. Source deletion or account-deletion fencing deletes derivatives, and a canceled deletion cannot restore a retired worker's lease. Auth deletion also cascades index rows. Account export retains the user-created originals and source metadata in their existing tables. Rebuildable embedding vectors and internal job state are excluded so redundant derivatives cannot exhaust the account export's size budget.

Each authenticated worker invocation admits at most 50 references, claims at most four jobs, and sends one bounded embedding batch through the existing embedding adapter with 1,536 dimensions and a 20-second timeout. Database statements have a five-second limit and client calls have a six-second deadline. Jobs retry at most three times with increasing delay; a changed source or embedding model allows new work. Admission stays below 2,000 index rows per source owner. Exact cosine over bounded PostgreSQL arrays avoids relocating or changing the existing vector extension; a future scale increase needs query-plan evidence before raising these bounds.

Hard provider ceilings are 100 worker invocations per day globally (at most 400 indexed records), 60 semantic queries per user per day, and 1,000 semantic queries per day globally. All searches also have a 30-per-minute per-user distributed limiter. A limiter failure prevents provider work. The worker has its own secret and does not reuse general cron credentials.

Activation requires the matching application and migration, verified embedding capacity/budget, `KOVA_WORKSPACE_SEMANTIC_ENABLED=true`, a dedicated `WORKSPACE_SEARCH_WORKER_SECRET`, and a scheduler calling `POST /api/internal/workspace-search` with its Bearer secret and no body/query. The flag and secret are off/empty by default. No live provider call, migration, secret, scheduler, or production setting was changed by this source work. Keyword search itself requires the new source view/RPC migration. If provider generation is disabled, derivative invalidation and deletion continue through database triggers.

Local executable coverage runs the real migration in PGlite and tests owner isolation, immediate shared Project revocation, deletion/recreation and account-fence races, malformed vectors, retry exhaustion, model compatibility, and lexical fallback. Hosted browser/database coverage and deployment verification remain release gates.
