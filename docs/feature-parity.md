# KovaGPT capability inventory

Last audited: **2026-07-29**. This matrix describes the checked repository and local test environment. It does not claim that credential-dependent production services were exercised.

## Status definitions

- **Working and verified locally** — implementation and its non-destructive local/browser boundary were exercised in this checkout.
- **Implemented; production configuration required** — the vertical slice exists, but a real provider, account, or production secret is required for an honest end-to-end check.
- **Partially implemented** — a useful workflow exists, but a material part of the category is absent.
- **Missing** — no production-capable implementation exists.
- **Intentionally unavailable** — omitted because the required provider, infrastructure, or safe product contract is not present.

## Implemented in this pass

1. **Private cloud-account exports.** Authenticated users can request, inspect, download, cancel, and expire owner-scoped account exports without public objects or exported credentials. A service-role worker leases each job, builds a bounded artifact, stores it privately, and settles completion exactly once.
2. **Versioned chat-history portability.** Device export now includes active chats, archived chats and local preferences, declares its device-only scope, and can be merged back through a bounded schema validator. Invalid, oversized, unknown-version and non-Kova files fail with useful errors. Newer existing chats win ID conflicts.
3. **Temporary-draft privacy.** Temporary chat now clears the current persisted draft, keeps subsequent unsent text in memory only, and reloads the normal per-chat draft after temporary mode is disabled.
4. **Truthful export copy.** Settings no longer describes a local browser JSON file as complete “account data.” Cloud records are explicitly excluded until an authenticated asynchronous export exists.

## Latest functional reliability pass

- Local text/code/CSV files are now first-class attachments with previews, removal, bounded content, server validation, model context, and device export/import preservation instead of being pasted into the prompt.
- Library attachments now resolve owner-scoped extracted content for the model; when extraction is unavailable, the model receives an explicit instruction not to claim it read the file.
- Generated images now expose a real clipboard-copy action, and their loading state describes only the provider request actually in progress.

- Editing a user prompt now replaces that turn and all later replies instead of appending a duplicate; image and Library attachments remain attached.
- Regenerating the latest answer preserves the original prompt attachments without duplicating the user turn.
- Delete and archive actions now provide working undo recovery, while the archive manager supports explicit bulk deletion.
- Imported device chats appear immediately in the workspace without requiring a reload.

## Recommended implementation order

1. **Complete cloud-account export:** add an authenticated, rate-limited export job with owner-scoped reads, an expiring download, audit logging and deletion lifecycle. Do not assemble all cloud records in the browser.
2. **Cross-device conversation persistence:** introduce an owner-scoped conversation/message schema, conflict/version semantics, migration from device storage and offline reconciliation.
3. **Library file versioning/folders:** requires schema, storage lifecycle and quota-aware server operations.
4. **Provider-dependent depth:** finish long-running research controls and only consider voice after a supported provider, metering, permissions, interruption and retention policy are approved.

## Production owner configuration still required

- AI/image/search provider secrets and model access must be configured server-side; verify quota, timeout and unavailable-provider paths after deployment.
- Supabase migrations, RLS and at least two isolated test users are required for Projects, sharing, Library, memory, scheduled tasks and deletion verification.
- Clerk/Google OAuth redirect URIs and credentials must match the production origin.
- Stripe webhook signing secret, products/prices and customer portal must be configured and tested with non-production payment accounts.
- The scheduled-task worker/cron and any connector sync workers must be deployed and observable.

No repository file, UI state, or local test in this audit establishes that those external systems are configured in production.
