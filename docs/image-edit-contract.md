# Image generation and private image edits

Image requests support one square (1024×1024), portrait (1024×1536), or landscape (1536×1024) image. Exact 16:9/9:16 and variation operations are rejected before the daily image quota. Azure output is PNG/JPEG; direct OpenAI additionally supports WebP. JPEG cannot request transparency. The response must contain one canonical base64 image with the requested format and dimensions; remote result URLs are not accepted.

Image editing is source-ready and disabled unless the operator explicitly configures `KOVA_IMAGE_EDITS_ENABLED=true` for an eligible configured GPT Image model/deployment. No provider, credit, quota, or deployment was changed by this source package. The existing provider authentication, model mapping and metering path is retained. Editing calls `/images/edits` with multipart source bytes, rather than describing a parent ID in a generation prompt.

The signed-in user selects an image already owned in their private Library. An edit source must be PNG, JPEG or WebP up to 8 MiB. An optional mask must be an alpha-channel PNG up to 4 MiB, with the same dimensions as the original. Transparent mask regions guide the model's requested changes; results are not a pixel-perfect preservation guarantee. Neither the source nor mask is overwritten. Uploading arbitrary URLs, other users' images, or unsupported masks is rejected. Source reads validate exact owner paths, signed-URL origin/path, container headers, dimensions and bounded byte counts. Codec decoding remains the provider's responsibility.

Library source discovery is deterministic and paginated. The UI fetches metadata only, and signs no preview URLs in the selection list. Before the provider call and again before returning generated bytes, the endpoint rechecks the verified principal, account deletion fence, and current source metadata. Requests have bounded JSON/body reads, provider result sizes and an abort lifetime. Result metadata includes the source item ID and SHA-256 of the actual source bytes. Prompt and image bytes are not logged. Generated browser history continues to use principal-scoped IndexedDB blobs; image bytes are not placed in localStorage. Explicit Library saves carry the initiating owner ID, so a delayed save cannot write private bytes into another signed-in account.

API contract references: [Microsoft's image generation guide](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/dall-e), [OpenAI image editing reference](https://developers.openai.com/api/reference/resources/images/methods/edit/), and [OpenAI image generation guide](https://developers.openai.com/api/docs/guides/image-generation). Activation still requires the configured deployment/capacity and acceptance checks by the operator; no live generation was used for tests.
