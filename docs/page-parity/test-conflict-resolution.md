# Test conflict resolution decisions

> **Historical and superseded (2026-09-02):** This table records earlier conflict decisions and is not current runtime or release guidance. In particular, its Lovable package, gateway, lockfile, email, and provider conclusions have been superseded by `docs/release-reconciliation/zero-lovable-classification.md`. Do not restore those dependencies or routes from this document.

| Test file / test                          | Stale assertion                                                      | Verified behavior and evidence                                                                                                                                  | Security / migration impact                                                                       | Resolution                                                                                                 |
| ----------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `connectors-governance` / Voice disabled  | Microphone must be globally denied                                   | `ChatInput` implements browser dictation; no full-duplex Voice control or provider audio route exists.                                                          | Denial broke the supported dictation product decision.                                            | Require `microphone=(self)` and retain absence of Voice UI/billing copy.                                   |
| `multimodal-scope` / provider Voice       | Both server headers must deny microphone                             | Browser read-aloud is local and dictation needs microphone; full-duplex provider Voice remains excluded.                                                        | Aligning `server.ts` and `start.ts` prevents deployment-specific permission breakage.             | Assert self-only microphone permission, local speech synthesis, and no provider audio secret/path.         |
| `lovable-removal` / private packages      | No `@lovable.dev` dependency may exist                               | Auth webhook and queue routes import `@lovable.dev/email-js` and `@lovable.dev/webhooks-js`; removing them breaks operational email.                            | Server-only imports remain authenticated/signed; no browser secret is introduced.                 | Assert packages exist only while operational routes import them.                                           |
| `lovable-removal` / provider gateway      | No managed gateway identifier may exist                              | Provider code has two compile-time constant endpoints and no environment-controlled base URL.                                                                   | Fixed allowlists prevent SSRF/configuration escape; Azure migration validation remains untouched. | Test absence of configurable endpoint knobs rather than banning the required managed path.                 |
| `lovable-removal` / Bun lock              | Bun lock must be absent                                              | Repository includes `bun.lock`, `bunfig.toml`, npm scripts, and `package-lock.json`; both workflows are intentionally checked in.                               | Deleting either blindly would make one supported workflow nondeterministic.                       | Assert both authoritative locks exist and npm lockfile is v3.                                              |
| `openai-runtime-security` / Responses API | Managed provider must not exist                                      | `chatCompletions` always adapts through `/responses`; base URLs are fixed constants and secrets remain server-only.                                             | Preserves provider abstraction and kill switch.                                                   | Assert Responses adapter plus fixed endpoints and no configurable/Vite secrets.                            |
| `openai-runtime-security` / ceilings      | Old ceilings were 600/4,000                                          | Current catalog authoritatively defines 1,200 instant and 16,000 deep ceilings; chat derives the cap server-side.                                               | Tests now match deployed policy without permitting client overrides.                              | Update exact catalog assertions.                                                                           |
| `provider-architecture` / endpoint        | Only direct OpenAI may exist                                         | Managed gateway is an operational path; Azure staging validation also exists, while the runtime adapter retains direct rollback.                                | Provider endpoints remain compile-time allowlisted with redirect errors.                          | Assert both fixed endpoints and selection expression.                                                      |
| `release-remediation` / Images attachment | No attachment icon, plus IME contract                                | The Images control only displayed a toast and did not map reference data to the authenticated generation route.                                                 | Removing the dead control avoids a false support claim; generation isolation remains unchanged.   | Remove dead chooser and add IME-safe Enter handling with an accurate accessible label.                     |
| `review-findings` / model selector        | Both files must directly call an obsolete helper                     | `ModelSelector` is a compatibility alias; `ResponsiveModelSelector` calls `versionGroupsForTier(userTier)`, hides guests, and server chat enforces entitlement. | Prevents UI-only paid model unlocking and removes stale source-shape coupling.                    | Assert alias wiring, tier-group helper, guest lock, and server reasoning enforcement.                      |
| `zero-lovable-provider` / no credit path  | Scan must reject every operational managed email/provider identifier | Managed email routes and fixed AI gateway are current production dependencies; configurable base URLs and public keys remain forbidden.                         | Keeps callbacks/email working without weakening endpoint or secret controls.                      | Replace name-based ban with fixed endpoint, server-only secret, signature, and Azure readiness assertions. |

All resolutions preserve the Azure deployment files, Supabase RLS, Stripe enforcement, authentication callbacks, and server-owned entitlements. No failing test was skipped or deleted.
