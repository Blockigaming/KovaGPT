# Browser preview and takeover boundary

The chat activity card is a recorded event, not a live session. Current Activity data has only tool, label and status, with no owned Work run/session reference. It does not export screenshots or control URLs. The card therefore opens an honest activity explanation and the existing Work route. It cannot claim live pixels or enable takeover for an unbound chat event.

The Work browser card reuses owner-authenticated /api/work/browser, expected run revision and session sequence. It shows a labeled text snapshot and opens the existing node controls. Pause the Work run first and wait for no pending step/effect; takeover then blocks model access. Return control releases ownership while the run remains paused. Resume run is a separate explicit action. End session closes the owned session. Closing the panel never resumes automation.

The isolated Browser activity presentation uses a synthetic landscape thumbnail and local state machine. Pause, Take over, editable sample text, Return control, Resume automation and End session change only sample state. No provider URL, real website, microphone or network action is involved.

Live visual-preview completion requires a reviewed ephemeral screenshot contract, owner/session authorization, redaction and retention rules, and a real chat-to-Work session binding. Existing screenshot-export restrictions and network authorization remain unchanged. The prepared Browser Use lifecycle client remains disabled and unconnected.

The owner's gray-outline dimension request is separate and pending identification; this revision does not widen unrelated controls.
