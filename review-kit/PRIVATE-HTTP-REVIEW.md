# Private HTTP review adapter

This optional review-only adapter serves the actual compiled Kova app to an ordinary browser. It imports the existing bundled review fixtures as local HTTP handlers. No Playwright, CDP, browser interception, production authentication bypass, provider credentials, new dependencies, deployment or publication is involved.

## Run

Keep the packaged, guarded application server running on `127.0.0.1:4189` using its existing `serve.mjs`. Start the adapter separately:

```sh
node /absolute/path/to/private-http-review.mjs --package=/absolute/path/to/KovaGPT-Recovery-Candidate-5502efb --port=4191
```

From the source checkout, the script is `review-kit/private-http-review.mjs`. The `--package` argument can point at another complete review package. It must include `SOURCE.json`, `dist/client`, `review/base-fixture.mjs`, `review/crud-fixture.mjs`, the scenario fixtures and the function manifest. Before listening, the adapter verifies that `/api/version` on the guarded upstream matches that package's `buildCommit`. The source/build identities are shown in the controls. An adapter copied alongside a package's `SOURCE.json` defaults to that package.

Open `http://127.0.0.1:4191/__local-review` in the normal browser. Choose Guest / Free / Plus / Pro, theme, route, Library / Projects / Tasks state, scenario and viewport, then click **Open / reset synthetic review**. That visible action deliberately clears this dedicated origin's local/session storage and its known `kovagpt-chat-history-v1` IndexedDB database, seeds disposable synthetic values and opens the application in a same-origin iframe. It does not alter browser prototypes or conceal browser automation. Reset discards the preceding session's server-side fixture data.

The controller can be hidden and restored. Viewports are 320×700, 375×700, 390×844, 430×800, 768×1024, 820×1180, 1024×768, 1440×900, 1920×1080 and 844×390 CSS iframes; this is not device emulation or certification of touch, virtual keyboards, camera, clipboard, native window sizing or physical-device behavior. Changes in the product can persist in its ordinary localStorage until reset. The adapter keeps up to 24 local sessions in memory; restarting it discards all of them. One browser origin shares the current account selection across its tabs.

Existing local fixtures support Projects create/edit/delete; Library item editing/removal, folders and movement; synthetic project upload/read/download/remove; and the explicit image, chat-outputs, tasks-editor, onboarding, recovery and billing scenarios. Scenario restrictions remain visible and enforced. Two default conversations use the current history contracts from `src/routes/api/chat/history.ts`, `src/lib/chat-history-state.mjs` and `20260905023609_chat_history_sync.sql`. The adapter supports disposable rename/pin/unpin/archive/restore on these samples only, as detailed below. No live synchronization is claimed. Close other private review app tabs if they block the explicitly requested database reset.

The **Library / Projects / Tasks state** selector supplies explicitly synthetic **empty**, **error**, and **loading** states for Library item-list reads and the existing `listProjects` / `listScheduledTasks` directory-read contracts. Project detail, files, members, Library detail/history, and mutations remain on their existing fixtures. Guest/signed-out access remains blocked for these overrides; Library list reads retain the sample-owner check. The state selector does not enable a scheduler or change Free-plan execution gates. This corrects the older broad Library wrappers: empty/error no longer replace item detail/history or mutation responses with list-shaped data, and their list overrides cannot bypass the sample-owner gate.

- **Synthetic empty** returns the normal empty-list envelope. It also removes the synthetic browser conversation seed, active-chat/draft references, synced HTTP history, and Library workspace-recents rows, so the default Library is genuinely empty. Reset clears the dedicated origin's local/session storage and known history database first. Explicit chat scenarios retain their own conversations, and explicit image scenarios retain their matching item responses.
- **Synthetic error** returns a simulated list-read failure (HTTP 503), allowing the product's own error UI to appear. Empty/error list responses stay fixed until reset; use **default fixture data** for ordinary CRUD review.
- **Synthetic loading · 20 second hold** holds each matching list request for up to 20 seconds, then returns a clearly labeled synthetic HTTP 503. It never falls through to a populated fixture or a live backend after the hold. Reset, sign-out, browser request abort/disconnection, session eviction, and normal adapter shutdown cancel owned timers. There are at most 64 pending holds per session, with an explicit local error for overflow. Reset to inspect loading again. This is a bounded inspection window, not a permanently pending request or an assertion about production latency.

Explicit scenarios take precedence for their matching handlers, so **tasks-editor** still supplies its two editable tasks even when empty/error/loading is selected, and image sample scenarios still provide their synthetic Library image. Unrelated list reads retain the selected state. Default fixture data does not promise every directory has records.

Default scheduled tasks have no execution service; use **tasks-editor** with any signed-in account (Free, Plus or Pro) to inspect the existing task editor with disposable records. Sample images use the bundled origami image, including edits. Trial and billing states are synthetic and cannot purchase or change a subscription. Plugin and core proposal previews remain separate links.

Task access in application source is now account-based; guests remain excluded. This draft changes neither live scheduler activation nor stored quotas. The existing `20260905005111_scheduled_tasks_activation_foundation.sql` admission, worker and connection policy still restricts execution to Plus/Pro and assigns Free a capacity of 0; `20260905013636_scheduled_task_verified_event_ingress.sql` also retains paid-plan event checks, and `security-governance.server.ts` retains the same numeric limits. Live Free execution therefore still needs an approved backend quota/admission change and deployment verification. The disposable task-editor scenario exercises create, edit, history, pause, resume and delete for Free/Plus/Pro without executing or delivering anything.

## Safety boundaries

- Binds only `127.0.0.1`, with exact Host validation, cross-site request rejection and same-origin mutation checks. Reset also requires the controls' CSRF value.
- The startup egress guard permits this Node process to contact only the existing loopback app on port 4189. The upstream remains independently guarded and receives no browser cookies, bearer headers or request bodies from the adapter.
- Only public HTML page rendering is forwarded upstream. APIs, auth calls, server functions and private-file fixture responses are local handler calls; unmatched handlers never forward to a provider.
- Served text rewrites only the exact known public Supabase origin, its publishable identifier and the existing fixture loopback URLs. On-disk compiled files and production source are not changed. All browser service calls target the same-origin review namespace.
- Synthetic tokens are explicitly unsigned, local-only placeholders for the compiled SDK's session shape. They contain an `.invalid` email and no real credential; they cannot authenticate to production. They are created only by the visible review reset action.
- CSP blocks external connections, scripts, fonts, images and media. Service workers, WebSocket upgrades, camera, microphone, geolocation and payments are disabled. No third-party service can operate through this adapter.
- Static file serving is confined to the packaged public assets with realpath containment. Private source, server bundles, credentials and the filesystem are not exposed.
- This is an isolated local inspection surface. It must not be deployed, reverse-proxied publicly or added to production routes.

Ctrl+C stops only the adapter. It leaves the independently running app on 4189 and any other preview server unchanged.
